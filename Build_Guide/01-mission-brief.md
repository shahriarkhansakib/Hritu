# Mission brief

*What is confirmed, what is not, and how to use this guide.*

This is the technical companion to the Participants Guide. The Participants Guide tells you when to show up, what to upload and how you are scored. This one tells you what to build and how to build it so that it still works when the venue wifi dies at 4pm on Saturday.

## The 2026 challenge list is confirmed

Fourteen challenges are published under the theme **The Next Frontier**. Every title in the draft blueprint set matches the official 2026 list — nothing is a 2025 carry-over, and nothing is missing. Only the *summaries* are live right now. The full statements, with NASA's own named datasets, publish on **28 October 2026**.

## The three sentences that decide your score

1. **NASA data is the evidence layer, not a decoration.** Relevance asks whether the project is NASA-data-first or NASA-data-added. Name the dataset on camera and in the project page.
2. **Deterministic code does the science; the model explains it.** Statistics, geometry, routing, similarity and simulation physics belong in your own code. The language model retrieves, orchestrates, explains and narrates.
3. **The demo must run with the wifi off.** Cache everything before the event and record a fallback video.

## How to move through this guide

The shared build kit is written once and applies to all fourteen projects — architecture, data access, batch and streaming, APIs, agents, MCP servers, skill files, judging and submission. Then each challenge has its own page with five tabs: the brief and the killer demo, the 48-hour plan, the data, the architecture, and a build prompt you can paste straight into an agent.

> **Critical**
>
> **Three rules that disqualify work.** Everything you build during the weekend stays open source — if you name no license, NASA distributes it under Apache 2.0. Every source is cited, even the free ones. No recognisable name, voice or likeness of anyone under 18 appears in any video or submission.
